# Where Protasena falls short of Proteus

> **Last reviewed:** 2026-10-20 · **Last updated:** 2026-10-20 · **Change:** minor (S2: default packages, pack memory; S3: unsaved changes on Exit) · **Target:** Labcenter Proteus 8 Professional (Windows)

Every known shortfall, one row each, ranked within each section by user impact. This is the work
list: agents pick from here (top of a section first), and remove or update a row in the same PR
that closes it. "Est." means a judgement, not a measurement.

## Schematic capture (milestone 1)

| # | Gap | Why it ranks here | Plan task |
|---|---|---|---|
| S1 | The window exists (M1 Task 9: `apps/protasena`, `crates/ui-egui`) but nothing of it is compared with Proteus beyond the layout order of the menu bar, the toolbar band and the status bar (`docs/ui-parity.md`: 3 of 253 rows match, measured). Every click, enabled rule, tooltip and dialog is still to observe; 91 menu items, 16 toolbar buttons and 14 modes have no command and are shown disabled | Behaviour is the baseline, and it has not been seen | Observation (needs Proteus driveable: non-elevated or an elevated shell) |
| S2 | The parts pack loads in the background (`--library` or `PROTASENA_LIBRARY_DIR`; 22 583 devices in about 1.3 s with a peak of about 205 MB resident, measured on a release build with `crates/library/examples/pack_stats.rs`; it was 1.9 s and 1.24 GB before equal symbols and pin maps were shared and package files read on first use); pack devices replace the built-in parts of the same name (`RES`, `CAP`, `NPN`… then use KiCad's symbols and pin numbers). Converter approximations: pin graphic styles are drawn as body graphics (the device model has no pin style), pin alternate functions are dropped, footprint zones and arcs inside footprint polygons are skipped. Default packages: the common parts (`RES`, `CAP`, `CAP-ELEC`, `DIODE`, `LED`, `NPN`, `PNP`, `74LS00`, `4001`, op-amps, …) get a conventional through-hole package from `map.toml`, the rest their KiCad `Footprint` field, else their first through-hole link — Proteus's default packages to compare | Converter approximations show in previews | M1 follow-up (library, libconv) |
| S3 | Save/Open/Export Netlist are reachable (menus, toolbar, keys; the system file chooser). Not built: Close Project, recent projects, auto-save and backups as Proteus does them (not observed). Opening a `.pdsprj` imports it and the project has no file, so Save asks for a new `.psproj`. New, Open, Exit and the window's close button ask our own Save / Don't Save / Cancel question while there are unsaved changes — Proteus's prompt to compare | Daily file workflow | M1 follow-up; observation |
| S4 | The engine (`crates/engine`) has 63 commands (measured) and interactive machines for 8 of the 22 modes (Selection, Component, Junction Dot, Wire Label, Text Script, Buses, Terminals, 2D Graphics Text). **Missing:** Subcircuit, Device Pins, Graph, Active Popup, Generator, Probe, Virtual Instruments and the other 2D graphics modes (they report "not available yet"); Text Script places plain text (no script semantics); Search & Tag, Property Assignment Tool, Align, Send To Back/Bring To Front, Tidy Design, Make Device/Symbol, Packaging Tool, Decompose; bus entries cannot be placed and buses carry no nets; multi-gate parts are not given the next free gate when placed. **Built the conventional way, to compare with Proteus** (its clicks and dialogs were not observable yet): Component mode shows a ghost at the cursor and places on one click (Proteus may pick up and then place), a click on a placed part selects it; real-time annotation on placement and the reference/value text positions; the wire autorouter's choice of path (L, Z through the middle, detours one grid step beyond bodies and connection points, a one-grid stub out of pins), straight (possibly diagonal) segments between clicked corners when the autorouter is off, how a wire ends (click on a pin, wire, junction or terminal; a second click on the same point; double click) and is cancelled (Escape, right button), automatic junction dots at T's; dragging stretches attached wires with an elbow or routes them again, Block Move keeps wires attached too, rotate/mirror of a selection turns each part about its origin with wires following, Block Rotate turns about the snapped centre of the selection, which axis X-Mirror and Y-Mirror flip; Delete keeps the wires of a deleted part, the Delete key itself (no menu item carries it); paste and Block Copy give colliding references the next free number and default to the cursor position; box selection takes only fully enclosed objects, Ctrl/Shift add and toggle; Zoom In/Out by a factor of 2 keeping the centre (Proteus may centre on the cursor), Toggle False Origin at the cursor, a 6-pixel pick tolerance; Global Annotator defaults to incremental; new sheets are named `Root sheet N`, a new project `UNTITLED`. Undo keeps 1000 steps and the design stays marked changed after undoing back to the saved state (Proteus's undo depth and title-bar marker to compare). Every dialog (Pick Devices, Edit Component, Edit Wire Label, Edit Design/Sheet Properties, Global Annotator, file choosers) is a request to the UI; their fields are not observed | Commands are the whole editing surface | M1 follow-up; observation |
| S5 | `.pdsprj` reading is partial (`docs/pdsprj.md`). **Reads:** the container, the manifest, the `ROOT.DSN` header (dates, release, times), style names, the embedded library (symbol names; device definition texts by section), circuits with wires, buses, nodes (junctions), components (reference, value, device, origin, label positions, properties, pin links), terminals (symbol, label), generators and probes (read, not imported). **Does not read:** component and terminal orientation (imported unrotated), the y-axis direction (taken as stored, unconfirmed), the header's design-property texts, wire labels, bus entries, sub-circuits and further sheets, 2D graphics and free text, junction dots versus plain nodes (inferred: three or more links), simulation graphs and the simulation settings trailer, `ROOT.CDB`, script members, symbol graphics. Embedded device definitions are reported, not converted; projects that use the owner's own Proteus libraries need their own handling later. No `.pdsprj` writing (L3). **Sample plan** (Proteus saves of our own synthetic designs, once it runs non-elevated so it can be driven; one change per save, diffed against the previous): empty sheet; one resistor; the same resistor rotated 90°, 180°, 270° and mirrored X/Y; two resistors and one wire; a changed value; a wire label; each terminal kind (default, input, output, bidirectional, power, ground, bus); a junction dot; a bus with an entry; 2D line, box and text; a second sheet; design properties filled in | Opening Proteus projects; orientation is the largest visible error | M1 Task 10 follow-up (observation) |
| S6 | Dialogs are our own layouts, following each dialog's purpose: Pick Devices (keywords, category/sub-category/manufacturer lists with counts, results with Device/Library/Description, symbol and PCB previews; nothing listed before a query, exact name matches first), Edit Component (reference and value with Hidden, element, PCB package, properties grid), Edit Wire Label, Edit Terminal, text, Edit Design/Sheet Properties, Goto Sheet, Global Annotator, the ERC and Netlist Compiler results — **to compare**: field sets, order, defaults, tabs, what is remembered, OK/Cancel behaviour, which result windows Proteus shows | Dialogs are where most editing happens | Observation |
| S7 | Connectivity, naming and annotation rules not yet compared with Proteus: wires crossing or touching at bends, pin ends on wire interiors, label case and scope, terminal scope and unnamed power/ground terminals, hidden power pins, net name priority and `#NET` numbering, annotation order, default sheet names and sizes; the engine adds a junction dot where a new wire ends on another wire's interior or where three wire ends meet, and a wire label must sit on a wire (within 1 th) — to compare | Netlists must match Proteus for the same design | M1 Task 6 follow-up (observation) |
| S8 | Window behaviour built the conventional way, to compare: the object selector caption per mode (Selection shows DEVICES; Junction Dot, Wire Label, Text Script, Buses and Active Popup show none) and the DEVICES order (order of picking); the P button opens Pick Devices only in device modes; grid drawn as dots by default and coarsened ×5/×2 when dense, Toggle Grid only on/off (whether G cycles dots/lines/off); wheel zoom by 2 per notch about the cursor; the overview pans on click and drag; the angle box shows the next placement's angle; toolbars wrap onto a second row and the left toolbars into a second column when the window is small; the coordinates field shows the snapped cursor; reference/value texts of new parts go above/below the body or beside it when a pin leaves upwards | The window must feel like Proteus | Observation |
| S9 | Window parts not built: toolbar tooltips beyond the button name, mnemonic underlines and Alt-key menu access, the tab close cross, graph tabs, the resizable overview with a remembered size, Pick Terminals and the other pickers, the library manager (L), right-click context menus, drag-and-drop of files, a remembered window layout per project | Smaller daily frictions | M1 follow-up |
| S10 | Product-name items: Help ▸ "About Proteus 8" is "About Protasena" and "About Qt" is left out; the title bar reads `<project> - Protasena - Schematic Capture` | Names of Labcenter's products cannot be ours | Owner decision (★ candidate) |
| S11 | The interface theme (light default, dark) is chosen only with `--theme`, `PROTASENA_THEME` or the control channel: Proteus has no theme choice and a menu place for it needs the owner's approval | Discoverability of the dark theme | Owner decision (★ candidate) |
