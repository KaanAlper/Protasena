# Where Protasena falls short of Proteus

> **Last reviewed:** 2026-10-20 · **Last updated:** 2026-10-20 · **Change:** minor (S2: pin alternates kept, pack version 2) · **Target:** Labcenter Proteus 8 Professional (Windows)

Every known shortfall, one row each, ranked within each section by user impact. This is the work
list: agents pick from here (top of a section first), and remove or update a row in the same PR
that closes it. "Est." means a judgement, not a measurement.

## Schematic capture (milestone 1)

| # | Gap | Why it ranks here | Plan task |
|---|---|---|---|
| S1 | The window exists (M1 Task 9: `apps/protasena`, `crates/ui-egui`) but nothing of it is compared with Proteus beyond the layout order of the menu bar, the toolbar band and the status bar (`docs/ui-parity.md`: 3 of 269 rows match, measured). Every click, enabled rule, tooltip and dialog is still to observe; 66 menu items, 12 toolbar buttons and 8 modes have no command and are shown disabled | Behaviour is the baseline, and it has not been seen | Observation (needs Proteus driveable: non-elevated or an elevated shell) |
| S2 | The parts pack loads in the background (`--library` or `PROTASENA_LIBRARY_DIR`; 22 583 devices in about 1.5 s with a peak of about 255 MB resident since pin alternates are kept (216 MB without them), measured on a release build with `crates/library/examples/pack_stats.rs`; it was 1.9 s and 1.24 GB before equal symbols and pin maps were shared and package files read on first use); pack devices replace the built-in parts of the same name (`RES`, `CAP`, `NPN`… then use KiCad's symbols and pin numbers). Converter approximations: pin graphic styles are drawn as body graphics (the device model has no pin style), pin alternate functions are kept (1 344 910 in the pack, pack format version 2; version 1 packs still load) and listed in Pick Devices and Edit Component, but a placed pin cannot be switched to one and the 138 alternates with a graphic style of their own lose it, footprint zones and arcs inside footprint polygons are skipped. **The user's own KiCad libraries** (System Settings ▸ KiCad libraries: `.kicad_sym` files, `.pretty` folders or folders holding them) are converted at run time by the converter's code (`crates/libimport`) and cached per file modification time and size under the user's cache directory (`PROTASENA_CACHE_DIR`); their devices are listed under their KiCad library's name, may repeat names of the pack (a plain name finds the pack's first), and problems (missing paths, files or symbols that do not convert, renamed clashes: a taken library name gets `_KICAD`, a taken package name becomes `Library:Name`) are reported, never fatal. Not built: links from imported symbols to the pack's footprints (only footprints imported from the same path are linked), a map of categories for them (the category is the library name), Proteus's Library ▸ Import Parts. Default packages: the common parts (`RES`, `CAP`, `CAP-ELEC`, `DIODE`, `LED`, `NPN`, `PNP`, `74LS00`, `4001`, op-amps, …) get a conventional through-hole package from `map.toml`, the rest their KiCad `Footprint` field, else their first through-hole link — Proteus's default packages to compare | Converter approximations show in previews | M1 follow-up (library, libconv) |
| S3 | Save/Open/Export Netlist are reachable (menus, toolbar, keys; the system file chooser). Not built: Close Project, recent projects, auto-save and backups as Proteus does them (not observed). Opening a `.pdsprj` imports it and the project has no file, so Save asks for a new `.psproj`. File ▸ Export Graphics writes the current sheet as PNG, BMP, SVG, PDF (or every sheet, a page each), EPS or DXF, built the conventional way (our own dialog and print colours; vector files at real size, texts in Helvetica; bitmaps with our own stroke font) — Proteus's export dialogs and output to compare; Export Metafile, Export Vector File and Mark Output Area are not built. Print Design prints to a PDF file through the same writer (every sheet by default) and can open it in the system viewer; nothing drives a printer, and Print Setup and Printer Information are not built. New, Open, Exit and the window's close button ask our own Save / Don't Save / Cancel question while there are unsaved changes — Proteus's prompt to compare | Daily file workflow | M1 follow-up; observation |
| S4 | The engine (`crates/engine`) has 100 commands (measured) and interactive machines for 14 of the 22 modes (Selection, Component, Junction Dot, Wire Label, Text Script, Buses, Subcircuit, Terminals and the 2D Graphics Line, Box, Circle, Arc, Closed Path and Text modes). **Missing:** Device Pins, Graph, Active Popup, Generator, Probe, Virtual Instruments, 2D Graphics Symbols and Markers (they report "not available yet"); 2D graphics have no style (line width, colour, fill) and no edit dialog; Text Script places plain text (no script semantics); Make Device/Symbol, Packaging Tool, Decompose; bus entries cannot be placed and buses carry no nets; multi-gate parts are not given the next free gate when placed. **Built the conventional way, to compare with Proteus** (its clicks and dialogs were not observable yet): hierarchical design — Subcircuit mode draws a box (two clicks or a drag, named the next free `SUBn`), a click on its left or right edge adds a port of the PORTS list's kind (DEFAULT, INPUT, OUTPUT, BIDIR) after asking its name, Edit Subcircuit (double click) edits the name and ports; Goto Child Sheet (Ctrl+C, no menu item: context menus are not built) makes an empty child sheet named after the subcircuit the first time, Exit to Parent Sheet (Ctrl+X) returns with the subcircuit selected, Page-Up/Page-Down and the sheet lists follow the hierarchy (a root sheet, then its sub-sheets); copies of a subcircuit get no child sheet (a child sheet belongs to one subcircuit: Proteus's sharing of one circuit by several subcircuits is not built), deleting a subcircuit keeps its child sheet as a root sheet; Align Objects (edges or centres of the selection, moves rounded to the snap grid, wires following), Send To Back/Bring To Front (within the drawing order of each kind of object), Tidy Design (our own definition: unused devices leave the DEVICES list, junction dots on no wire or bus, zero-length wires and empty texts are removed); Search & Tag (operators equals/begins/ends/contains and their negations, less/greater by engineering value; new, AND and OR searches; current sheet only) and the Property Assignment Tool (assign `NAME=VALUE` with a `#` counter, rename `OLD=NEW`, remove `NAME`; on the tagged parts, the sheet or the design; Proteus's show/hide/resize actions and on-click use not built); the 2D graphics clicks (Line, Box, Circle: two clicks or a drag; Arc: start, end, then a point on the arc; Closed Path: a click per corner, closed by a double click or the right button), a graphic turning about its first point (a circle about its centre) and being hit on its outline only; Component mode shows a ghost at the cursor and places on one click (Proteus may pick up and then place), a click on a placed part selects it; real-time annotation on placement and the reference/value text positions; the wire autorouter's choice of path (L, Z through the middle, detours one grid step beyond bodies and connection points, a one-grid stub out of pins), straight (possibly diagonal) segments between clicked corners when the autorouter is off, how a wire ends (click on a pin, wire, junction or terminal; a second click on the same point; double click) and is cancelled (Escape, right button), automatic junction dots at T's; dragging stretches attached wires with an elbow or routes them again, Block Move keeps wires attached too, rotate/mirror of a selection turns each part about its origin with wires following, Block Rotate turns about the snapped centre of the selection, which axis X-Mirror and Y-Mirror flip; Delete keeps the wires of a deleted part, the Delete key itself (no menu item carries it); paste and Block Copy give colliding references the next free number and default to the cursor position; box selection takes only fully enclosed objects, Ctrl/Shift add and toggle; Zoom In/Out by a factor of 2 keeping the centre (Proteus may centre on the cursor), Toggle False Origin at the cursor, a 6-pixel pick tolerance; Global Annotator defaults to incremental; new sheets are named `Root sheet N`, a new project `UNTITLED`. Undo keeps 1000 steps and the design stays marked changed after undoing back to the saved state (Proteus's undo depth and title-bar marker to compare). Every dialog (Pick Devices, Edit Component, Edit Wire Label, Edit Design/Sheet Properties, Global Annotator, file choosers) is a request to the UI; their fields are not observed | Commands are the whole editing surface | M1 follow-up; observation |
| S5 | `.pdsprj` reading is partial (`docs/pdsprj.md`). **Reads:** the container, the manifest, the `ROOT.DSN` header (dates, release, times), style names, the embedded library (symbol names; device definition texts by section), circuits with wires, buses, nodes (junctions), components (reference, value, device, origin, label positions, properties, pin links), terminals (symbol, label), generators and probes (read, not imported). **Does not read:** component and terminal orientation (imported unrotated), the y-axis direction (taken as stored, unconfirmed), the header's design-property texts, wire labels, bus entries, sub-circuits and further sheets, 2D graphics and free text, junction dots versus plain nodes (inferred: three or more links), simulation graphs and the simulation settings trailer, `ROOT.CDB`, script members, symbol graphics. Embedded device definitions are reported, not converted; projects that use the owner's own Proteus libraries need their own handling later. No `.pdsprj` writing (L3). **Sample plan** (Proteus saves of our own synthetic designs, once it runs non-elevated so it can be driven; one change per save, diffed against the previous): empty sheet; one resistor; the same resistor rotated 90°, 180°, 270° and mirrored X/Y; two resistors and one wire; a changed value; a wire label; each terminal kind (default, input, output, bidirectional, power, ground, bus); a junction dot; a bus with an entry; 2D line, box and text; a second sheet; design properties filled in | Opening Proteus projects; orientation is the largest visible error | M1 Task 10 follow-up (observation) |
| S6 | Dialogs are our own layouts, following each dialog's purpose: Pick Devices (keywords, category/sub-category/manufacturer lists with counts, results with Device/Library/Description, symbol and PCB previews; nothing listed before a query, exact name matches first), Edit Component (reference and value with Hidden, element, PCB package, properties grid), Edit Wire Label, Edit Terminal, text, Edit Design/Sheet Properties, Goto Sheet, Global Annotator, the ERC and Netlist Compiler results — **to compare**: field sets, order, defaults, tabs, what is remembered, OK/Cancel behaviour, which result windows Proteus shows | Dialogs are where most editing happens | Observation |
| S7 | Connectivity, naming and annotation rules not yet compared with Proteus: the hierarchy's scopes (a subcircuit's port joins the child sheet's input, output or bidirectional terminal of its name; every other name on a child sheet is local and prefixed by the instance path, `SUB1.DATA`, except power and ground terminals, power symbols, hidden power pins and labels marked global; part references are not prefixed; a child sheet is connected once, for the first subcircuit reaching it), wires crossing or touching at bends, pin ends on wire interiors, label case and scope, terminal scope and unnamed power/ground terminals, hidden power pins, net name priority and `#NET` numbering, annotation order, default sheet names and sizes; the engine adds a junction dot where a new wire ends on another wire's interior or where three wire ends meet, and a wire label must sit on a wire (within 1 th) — to compare | Netlists must match Proteus for the same design | M1 Task 6 follow-up (observation) |
| S8 | Window behaviour built the conventional way, to compare: the object selector caption per mode (Selection shows DEVICES; Junction Dot, Wire Label, Text Script, Buses and Active Popup show none) and the DEVICES order (order of picking); the P button opens Pick Devices only in device modes; grid drawn as dots by default and coarsened ×5/×2 when dense, Toggle Grid only on/off (whether G cycles dots/lines/off); wheel zoom by 2 per notch about the cursor; the overview pans on click and drag; the angle box shows the next placement's angle; toolbars wrap onto a second row and the left toolbars into a second column when the window is small; the coordinates field shows the snapped cursor; reference/value texts of new parts go above/below the body or beside it when a pin leaves upwards | The window must feel like Proteus | Observation |
| S9 | Window parts not built: toolbar tooltips beyond the button name, mnemonic underlines and Alt-key menu access, the tab close cross, graph tabs, the resizable overview with a remembered size, Pick Terminals and the other pickers, the library manager (L), right-click context menus, drag-and-drop of files, a remembered window layout per project | Smaller daily frictions | M1 follow-up |
| S10 | Product-name items: Help ▸ "About Proteus 8" is "About Protasena" and "About Qt" is left out; the title bar reads `<project> - Protasena - Schematic Capture` | Names of Labcenter's products cannot be ours | Owner decision (★ candidate) |
| S12 | Template and System settings are built the conventional way, to compare: the template (design colours for paper, grid, highlight and drag; our own list of graphic styles and text styles; 2D graphics defaults; junction dot size and shape) is saved in the `.psproj` (format version 2) and undoable, every value optional so an untouched design keeps our own look; the system settings (library and project folders, display options, keyboard mapping, property definitions, sheet sizes, text editor) live in the user's `settings.json` (`PROTASENA_CONFIG_DIR`, else the platform's configuration directory) and are read leniently (a bad value falls back to its default with a warning). Differences we know of: exports and prints keep our print palette (template colours are on screen only), the library folder applies at the next start, only engine commands can be bound to keys. **Not built:** Template ▸ Goto Master Sheet, Set Graph & Trace Colours, Apply Styles From Template, Save Design as Template; System ▸ Text Viewer, Set Animation Options, Set Simulation Options | Settings shape every session | Observation |
| S13 | The Bill of Materials (Global Toolbar) is our own report window, to compare: one line per value, device and package with the quantity and the references in natural order, the device's description; all sheets, power symbols left out, gates counted once, unannotated parts one by one; CSV (RFC 4180, formula-like cells defused with a leading `'`) and HTML exports, and a JSON form. Proteus's Bill of Materials module (categories, columns, report templates, stock codes, costs) was not observed and is not built | Parts lists are a daily output | Observation |
| S11 | The interface theme (light default, dark) is chosen only with `--theme`, `PROTASENA_THEME` or the control channel: Proteus has no theme choice and a menu place for it needs the owner's approval | Discoverability of the dark theme | Owner decision (★ candidate) |
